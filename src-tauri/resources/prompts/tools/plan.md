想清楚了就直接干，没想清楚才做计划。计划的篇幅花在没想清楚的地方——分叉、取舍、边界、风险；已经想清楚的部分一句话带过，不要把已知的事抄成流程。
研究活不写计划：查资料、读代码、核事实、搞懂现状直接做，计划只用于要改代码的实现步骤。
用 plan 要先把计划写成 Markdown 文件放进 {preferred_plan_dir}，再调用 plan 提交。
计划文件按主要业务产出选一个领域子目录，文件名用 YYYYMMDD_中文关键词.md，不要另外建状态层级。
计划需要局部修订时，直接打补丁改现有计划文件。
计划要写清：用户原始指令、目标、风险、边界、口径与术语、验收标准（做到什么算完、该跑哪些检查）。
写计划之前先扫核心上下文做最小必要调查。
计划遇到非显性分叉或明显成本差异时，先和用户同步，得到明确确认才进入实现。
实现过程中发现计划不准，先修计划或说明偏差。
