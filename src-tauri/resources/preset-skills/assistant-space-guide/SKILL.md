# 助理空间指南

## 适用范围

助理空间是助手跨会话、跨项目使用的长期私有区域。它承载共享能力和个人配置，不是当前用户项目的默认工作目录。

先区分三层边界：

| 位置 | 负责内容 |
| --- | --- |
| 当前会话工作区 | 当前项目的源码、配置、构建、测试和用户要求的交付。 |
| 项目 `.pai/` | 仅当前项目的 Skill、计划、报告、工作流、参考项目、隔离工作树和临时材料。 |
| 助理空间 | 跨项目复用的预置/私有 Skill、MCP、人格私有配置、共享资源和助手自身可归档产物。 |

涉及当前项目时，优先使用当前会话工作区与已注入的工作区说明；不得把调试文件、项目计划、项目代码或一次性产物写到助理空间来规避项目边界。

## 助理空间中的长期资产

- `skills/`：跨项目可复用的预置 Skill 和用户私有 Skill。项目专用规则应放在项目 `.pai/skills/` 或项目根目录的 `skill/`，不要误写入这里。
- MCP：助理空间当前承载可配置的 MCP 能力与相关私有资源。安装、配置、启用、停用或排查 MCP 时使用 `mcp-setup`。
- 人格与私有组织配置：只在用户明确要求维护私有组织时使用 `private-organization-guide`，不得把当前项目的组织约定擅自固化为全局规则。
- 跨项目资源与可归档产物：仅保存确实可跨项目复用、需长期保留且不属于某一项目的内容；使用清晰名称和用途说明。

项目 `.pai/mcp/` 是项目级 MCP 的预留边界，但当前 PAI 尚不支持项目级 MCP 自动加载或配置。不要把项目目录中的 MCP 文件当成已经生效的助理空间配置。

## 共享 Skill

助理空间中的 Skill 面向跨项目复用；项目专用规则应放在项目 `.pai/skills/` 或项目根目录的 `skill/`，项目工作流应放在 `.pai/workflow/`。发现项目级 Skill 或工作流缺失、过期或错误时，应在项目范围内创建、维护或修正，不要互相替代或重复堆放。

修改共享 Skill 前，先确认它是否会影响其他项目或会话。新增或调整后，确认名称、说明和适用范围一致，并确认当前配置下能够正常使用。删除、重命名或覆盖已有 Skill 前，先确认使用者和影响范围。

## 操作边界

- 助理空间不是通用临时目录。一次性调试报告、截图、实验脚本和构建产物应放在项目 `.pai/temp/`。
- 不要为每个项目在助理空间创建项目副本、`projects/`、`scratch/` 或平行计划目录。
- 不得用助理空间设置绕开当前项目的 `AGENTS.md`、用户指令、权限约束或 Git 规则。
- 修改共享能力前先确认它会影响哪些项目和会话；范围不明时先调查。
- 删除、迁移或清理助理空间文件前，说明范围和影响并取得用户明确确认。

## 完成前检查

1. 确认变更确实属于跨项目共享能力，而非单个项目资产。
2. 核对名称、说明、适用范围与当前配置下的可用性。
3. 不触碰当前项目的未提交改动或无关私有配置。
4. 汇报变更位置、实际影响范围和必要验证结果。
