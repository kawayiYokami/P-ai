# 记忆生成规范

## 核心目的：为了未来在特定情景下能被准确唤醒

记忆不是记录流水账，**它存在的唯一意义是：未来在某个场景下被问起、或遇到类似问题时，能被准确召回并直接派上用场。**

- **要不要记**：问自己一句——**“未来在某个场景下，我或用户会需要想起这件事吗？”** 会就记；拿不准时宁可记下，也绝不遗漏。唯一底线是有据可查，严禁脑补编造。
- **同类合并**：同一情景下的零散碎片合并为一条完整记忆，不要零碎分散。

---

## 1. 记什么（未来会用到的事实）

- **用户画像（未来理解与服务该用户的情景）**：
  从对话正文及问句从句中抽取长期特征：
  - `事实属性`：身份、所在地、生活习惯、稳定偏好、忌口（用于未来生活偏好、日常交互情景）
  - `技能树`：掌握或在学的语言、框架、工具（用于未来技术选型、代码编写、方案讨论情景）
  - `关系图谱`：合作者、团队、关注的人物或作品（用于未来协作、推荐、人际话题情景）
  - `活跃项目`：正在推进的项目、研究及阶段目标（用于未来进度跟进、背景代入情景）
  - `用户要求`：长期遵守的回答风格、禁忌、硬性约束（用于未来交互规范情景）
  - `用户别名`：稳定称谓或代号
- **经验教训（未来遇到类似任务/故障的情景）**：
  - 项目特殊约束、踩坑教训、报错排查结论（用于未来遇到相同错误或命令时直接避坑）

> **过滤线**：寒暄应酬、单次操作步骤、临时情绪与口误、密码/Token 等敏感信息**一律不记**。

---

## 2. 字段规范：围绕“未来怎么用”来写

每条记忆脱离当前对话也必须能被独立理解：

### judgment（未来能直接拿来用的明确结论）
- 一句客观陈述。写具体名词、数字原样照抄、时间写绝对日期（禁用“现在/目前/上周”）。
- 涉及用户写明身份：`真实昵称（真实用户ID）+ 结论`。
- *例*：`张三（user-persona）使用 Windows 系统开发 Tauri 2 + Vue 3 项目，包管理固定用 pnpm。`

### reasoning（判断理由）
- 未来召回这条记忆时，靠它知道为什么会有这个结论。
- 事实依据、日志、实测结果都可以，比如原话。
- 不写自我心理活动或主观推演。

### tags（核心：预测未来需要这条记忆的触发情景）
**tags 不是死板的分类标签，而是预测未来在什么情景下需要调出这条记忆。**
写 tags 时思考：**“未来用户聊到什么话题、遇到什么问题、执行什么任务时，系统需要立刻唤醒这条记忆？”**

- **标签规则（严格遵守）**：
  1. **用户画像固定锚点**：必须包含 3 个基础项：`[真实昵称, 真实用户ID, 画像属性类型]`。
     - **真实昵称与ID**：本地用户ID为 `user-persona`；远程用户取发言人元信息；严禁把“真实昵称”“用户ID”这些占位词原样写入。
     - **画像属性类型**：必须且只能从以下六个固定词中选择其一：`事实属性`、`技能树`、`关系图谱`、`活跃项目`、`用户要求`、`用户别名`。
  2. **助手经验基础锚点**：写具体技术名与项目名（如 `Rust`、`Tauri`）。
  3. **情景预测词（最关键）**：未来可能触发此记忆的**具体场景、关联问题、操作动作、话题关键词**。
- *示范 1（用户画像 - 饮食偏好与禁忌）*：
  - `judgment`: `李四（user-persona）对花生严重过敏，且饮食习惯不吃辛辣。`
  - `tags`: `["李四", "user-persona", "事实属性", "花生过敏", "辛辣禁忌", "点餐推荐", "餐厅挑选", "做菜谱", "饮食偏好"]`
  - *（预测情景：未来无论用户问“附近有什么好吃的”、“帮我做个晚餐食谱”，还是聊到点外卖，都能凭情景词立刻命中该忌口）*
- *示范 2（助手经验 - 编译踩坑）*：
  - `judgment`: `Windows 上 cargo check 若项目路径含中文，会触发 link.exe LNK1104 找不到文件，需将 CARGO_TARGET_DIR 设置为纯 ASCII 路径。`
  - `tags`: `["Rust", "cargo check", "Windows中文路径", "link.exe", "LNK1104", "编译报错排查", "环境配置"]`
  - *（预测情景：未来只要发生构建失败、LNK1104 报错，排查场景就能立即召回该方案）*

## 3. 动作判定（增 / 改 / 并）

根据与已有记忆的关系选择动作：

- **update（修改）**：新事实与已有记忆**冲突**（偏好变迁、用户纠错），或旧记忆需要**就地补充新细节**。用最新事实覆盖旧记录，保持标签体系一致，消除冲突。
- **merge（合并）**：多条已有记忆属于**同一情景下的零散切面**（例如一条记了用 React，一条记了用 Vite）。将它们融合成一条更完整、更通用的记忆，合并并丰富场景 tags，防止记忆库碎片化。
- **create（新增）**：全新情景与主题的事实。

---

## 4. 提取要点（确保未来能召回、能用上）

1. **写具体，不抽象概括**：原文说“喜欢徒步和钓鱼”，就写徒步和钓鱼，不要概括成“喜欢户外运动”；专有名词不擅自替换。
2. **问句里的从句也要抽**：用户在提问、吐槽时顺带透露的拥有物与经历也是事实（例：“我新买的索尼微单怎么连电脑” → 抽用户拥有索尼微单；预测情景：摄影、选镜头、数码配件）。
3. **枚举列表逐条拆开**：助手给的大段清单拆成独立条目记录，保留序号与名称，不合并压缩成一句话。
4. **时间写绝对日期**：原文明确日期照抄；相对时间（“昨天”、“下个月”）按会话时间换算为具体日期，防止未来失效。
