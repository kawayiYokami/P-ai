# 经验与教训维护

## 目标

把已经验证过、未来还会复用的经验，沉淀成按主题划分的独立 Skill，避免混入项目规则、用户记忆或普通聊天记录。

主题 Skill 的名称统一为：

> 关于【主题】的经验与教训

例如：

- 关于 PAI 开发的经验与教训
- 关于跟用户沟通的经验与教训
- 关于网页搜索的经验与教训
- 关于代码审查的经验与教训
- 关于 Skill 制作的经验与教训
- 关于界面视觉调整的经验与教训

## 记录原则

只记录可复用、已验证的经验；不记录临时参数和猜测。

## 先找主题，再决定是否新建

1. 先检查已有的“关于……的经验与教训” Skill。
2. 能自然归入已有主题，就追加到已有主题，不新建文件。
3. 只有现有主题无法清楚容纳时，才新建主题。
4. 主题应按工作领域划分，不按单个项目划分；项目专属规则仍写项目 `AGENTS.md` 或 `.pai/`。
5. 主题过大、经验彼此无关且检索困难时，再拆成两个主题。

## 每条经验怎么写

每条经验只需要有独立的标题和内容，具体形式自由：可以是成功做法、失败教训、流程诀窍、验证结论或其他可复用信息。

不要规定固定字段、固定顺序、固定编号或固定段落结构。严禁把经验模板写成一二三四五，也不要为了更新一条经验而改动其他条目的结构。

```markdown
### 简短标题

正文内容按经验本身组织。
```

内容粒度按来源决定：从文档中学到的内容只提炼必要经验，不抄录整篇文档；通过自身探索、试错或工作获得的经验，应保留足够详细的过程、判断和结果，确保未来能够复用。不要记录情绪、重复背景或无法验证的推测。

## 新增主题 Skill

当现有主题无法自然容纳新经验时，按复用范围选择位置：跨项目通用的 Skill 放在助理空间的 `skills/` 目录下，并主动通过 PAI 配置挂载到当前人格；只属于当前项目的 Skill 放在当前工作目录的 `.pai/skills/` 下，由项目机制自动扫描并作为可选 Skill 暴露，无需手动挂载。新建对应目录和 `SKILL.md`，写明适用场景与经验条目。

## 维护规则

- 主题 Skill 必须按条目维护，每条经验独立成段。
- 每次维护只能选择：新增一条经验，或更新一条已有经验。
- 严禁为了加入新经验而完整重写整个 Skill。
- 新经验优先修正旧条目，不要留下互相冲突的两条规则。
- 用户明确改变要求时，以最新要求为准，并只更新受影响的条目。
- 同一经验反复出现时，合并成一条更明确的规则。
- 发现经验只适用于某个项目时，将它移出主题 Skill，放回项目能力资产。
- 主题 Skill 只写经验与教训，不承担完整流程、项目说明或用户画像功能。
- 修改共享主题 Skill 前，确认它确实适用于多个项目；否则不要放在助理空间。
- 单个 Skill 文档超过 300 行时，主动按职责或主题拆分成多个 Skill，保持主题清晰；拆分时只迁移原有条目，不因拆分而重写内容。
