# 远程群聊能量机制设计

## 目标

让远程群聊中的助理像一个会看群、会控制发言欲望的普通成员：被点名时会尽快看见并理解消息；未被点名时按自己的巡检节奏观察群聊；连续说得多会消耗能量，安静一段时间或收到正面反馈后才更愿意再次参与。

这是当前远程群聊能量机制的现状说明，实现见 `src-tauri/src/features/remote_im/group_reply_energy.rs`。私聊不经这套能量门控；群聊无论智能判断还是始终回复，巡检到期后都先过 `remote_im_group_reply_gate`。始终回复只在过门后跳过秘书，直接当作应回复。

## 入场先于巡检

巡检不是收信入口。每条群聊消息都先入库；只有消息通过联系人入场模式后，才会创建一个可以巡检的当前批次：

```text
始终入场：通过
点名入场：仅命中点名词时通过
不入场：不通过，只保留消息
```

没有入场，就没有工作台可巡检。联系人曾经在场、曾经回复，或群里正在聊天，都不能绕过这道门槛。

一个批次一旦入场，入场消息是否点名决定它走哪条巡检路径；未冻结前收到点名消息会升级为点名巡检并保留原起点，普通消息只追加而不重新计时。范围冻结后，新消息只记录下一轮点名等级。

## 两类巡检路径

### 点名巡检：入场后直接交给助理

@ 助理、点名或唤醒词属于点名巡检。它们不是立即发送回复，而是把本批消息交给助理的时间提前到助理防抖结束：

```text
点名巡检时间 = 当前时间 + 助理防抖时间
```

助理防抖用于合并同一人紧接着补发的内容。到期后不经过秘书判断，直接由助理读取整批消息并处理；点名信号只表示“请助理现在看”，不保证必定外发回复。

发送前只检查当前能量是否严格大于 `0`，不估算正文成本，也不要求现有能量能够覆盖本次回复。当前能量小于或等于 `0` 时，本次点名巡检不再反复加速，未处理消息保留并回到下一次非点名巡检周期；当前能量大于 `0` 时允许正常回答，外发结算后可以变为负数。

批次起点由入场消息固定。未冻结前收到的 @、点名或唤醒词会把等待中的非点名巡检升级为点名巡检；范围冻结后收到的点名只影响下一轮，不改写当前范围。

### 非点名巡检：入场后由秘书判断

秘书防抖不是“每收到一条消息就重新倒计时”的传统防抖，而是联系人维度的随机巡检周期。

有新消息时，如果当前没有待执行的巡检，就开始一次周期；之后的新消息只追加到本批待观察内容，不改变已经排定的巡检时间。

```text
本次巡检间隔 = max(1 秒, 秘书基础间隔 × (1 + Uniform[-波动阈值, +波动阈值]))
```

例如基础间隔为 60 秒、波动阈值为 0.2 时，每次巡检间隔在 48–72 秒之间。波动只影响“什么时候看群”，不随机决定“要不要回复”。

非点名巡检到期后，才由秘书读取积累消息、判断是否和助理相关、是否值得在此时回复；秘书决定需要回应后，再交给助理生成实际回复。

## 一个巡检周期的处理顺序

1. 巡检到期读取起点以来积累的未处理消息并冻结本周期范围。
2. 对冻结范围结算正面词与负面词能量；同一个正面词在本周期内只计一次。
3. 若处于回复冷却期或结算后的当前能量小于或等于 `0`，不调用秘书，不丢弃消息，直接等待下一个随机巡检周期；重排同一范围时不重复结算入站能量。
4. 当前能量严格大于 `0` 时，秘书判断内容是否和助理相关、是否是合适的输出时机；不再检查预计字数成本。
5. 若秘书决定回复，交给助理生成并外发消息，按最终文本字数扣除能量；若决定不回复，将本批消息标记为已处理。

因此，能量小于或等于 `0` 不会把消息视为已处理；助理会在能量自然恢复或被正面词提升到严格大于 `0` 后，于后续周期重新获得一次机会。点名巡检与非点名巡检不混用：前者直接走助理，后者必须先走秘书判断。

## 能量账本

每个群联系人维护独立的运行时能量 `E`；渠道保存参数模板，但一个群里的连续发言不会拖慢同渠道的其他群。

```text
-最大能量 M ≤ E ≤ 最大能量 M；E 允许为负数，但不能低于 `-M`
初始能量 = M
E(t) = clamp(-M, M, E(上次记录) + 每秒回能 R × 经过秒数)
```

回复资格只判断巡检时的 `E > 0`。回复结算可以让 `E` 降到 `0` 以下，但最低只能到 `-M`，不能无限累积负债。负值必须原样保存在账本中并继续按上式恢复，不能在读取或保存时强制改写为 `0`。当恢复或正面词变化使 `E` 再次严格大于 `0` 后，下一轮才恢复回复资格。

能量恢复采用按需计算，不为每个联系人创建后台计时器。每个联系人只持久化 `energy` 与 `energy_updated_at`；在巡检检查回复资格、结算正负词或结算外发回复时，根据当前时间与 `energy_updated_at` 的差值计算恢复量。只读检查无需为了展示递增值而持续写盘；发生正负词变化或回复扣费时，才把结算后的能量和当前时间一起保存。即使连续多次只读都从同一个旧时间戳计算，累计恢复量也不会丢失。

```text
联系人检查点：energy、energy_updated_at
后台计时器：无
恢复触发：巡检资格检查 / 正负词结算 / 回复结算
状态写回：能量发生实际结算时
```

回能速度是渠道参数 `energyRecoveryPerSecond` 的直接数字，界面文案叫「回复热情 / 每秒回能」，不是 `0~1` 滑条，也没有热情度映射公式。默认每秒回能 `0.6`（`M=100` 时约每分钟 36）。该值只影响恢复速度，不直接强迫助理发言。

## 按字数消耗能量

回复不采用“每条固定扣能”。短句插话应当较轻，完整回答应当明显更贵。

```text
本次消耗 = 基础发言消耗 + 最终有效字数 × 每字消耗
```

“有效字数”使用实际外发文本去除 Markdown 标记后的非空白字符数；图片、文件和工具调用本身不计字数，图片说明文字照常计算。

流式生成前不预估、不冻结、不预留也不预扣能量，生成期间不随流式 delta 扣能。只要生成前检查到 `E > 0`，本轮就可以完整回答；最终正文实际外发后，再按同一份外发文本一次性结算：

```text
E(回复后) = clamp(-M, M, E(回复前) - 本次消耗)
```

结算不设置 `0` 下限，但设置 `-M` 下限，允许结果在 `[-M, 0)` 内为负数，不能无限扣除。最终没有回复或能够明确确认消息未发送时不扣；发送已经发生但结果无法确认时，按避免重复外发的 at-most-once 口径只结算一次。委托创建、模型生成、流式输出和必要的回复改写本身都不单独扣能。

推荐初始参数：

| 参数 | 代码默认值 |
|---|---:|
| 最大能量 | 100 |
| 基础发言消耗 | 14 |
| 每字消耗 | 0.12 |

对应的消耗为：

| 实际字数 | 20 | 40 | 80 | 200 |
|---:|---:|---:|---:|---:|
| 消耗能量 | 16.4 | 18.8 | 23.6 | 38.0 |

配置只需保证最大能量大于 `0`，基础发言消耗与每字消耗非负且有限；不再要求任何预计长度的回复成本小于最大能量，因为回复资格不以“能量足够覆盖本次成本”为条件。

## 正面词与负面词

每个渠道增加两套可编辑短语列表：正面词与负面词。它们只读取其他群成员新发出的文本，不读取助理自己的消息、历史引用或转发内容。

巡检冻结消息范围后，才更新当前群的能量：

```text
E = clamp(-M, M, E + 正面命中奖励 - 负面命中扣除)
```

正负词结算同样不设置 `0` 下限，但设置 `-M` 下限。负面词可以把能量降到负数但不能低于 `-M`；正面词可以从负数开始回升，并在结果严格大于 `0` 时恢复本轮后续的回复资格。

推荐默认幅度：

| 事件 | 默认变化（M=100） |
|---|---:|
| 命中一条正面词 | +6 |
| 命中一条负面词 | -15 |

匹配与防刷规则：

- 按短语匹配。默认正面词是「厉害」「像人」，负面词是「够了」「烦」「串了」；其中「烦」是单字。
- 同一轮巡检范围内，相同正面短语只计一次；正面和负面短语可分别命中后取净值。
- 本轮正、负变化各自最多为 `20% × M`。
- 巡检重排时保留“本轮能量已结算”标记，不重复处理同一冻结范围；应用重启后该轮自然放弃，不补算。

## 焦点指令

每个渠道增加一套可编辑的“焦点指令”短语。它表示群成员正在要求助理用心处理当前问题，例如：

```text
分析 好好想想 深入分析 认真想想 方案设计 评估 推导 复盘
```

命中焦点指令时，本批消息标记为 `focus=true`。它不强制回复、不绕过点名/非点名巡检规则、不绕过回复冷却，也不绕过 `E > 0` 的回复资格检查；本轮外发结算后仍允许能量降为负数。只有助理最终决定回复时，才切换本次注入给 LLM 的长度指令。

渠道配置提供一个“回复字数限制”控件，包含两个独立值：

| 参数 | 建议默认值 | 含义 |
|---|---:|---|
| 常规回复字数 | 20 | 未命中焦点指令时的回复上限。 |
| 焦点回复字数 | 200 | 命中焦点指令时的回复上限。 |

保存时校验 `常规回复字数 ≥ 1`、`焦点回复字数 ≥ 常规回复字数`。两者均由用户单独设置，不写死为 20 或 200。

| 本批状态 | 注入给 LLM 的长度指令 |
|---|---|
| 默认 | `请在 {常规回复上限} 个有效文本单位内进行回应。{计数规则}` |
| 命中焦点指令 | `请认真回答，最多 {焦点回复上限} 个有效文本单位。{计数规则}` |

计数规则：中文 / 日文 / 韩文按可见字形计 1，英语等按 Unicode 单词计 1，数字词和 Emoji 各计 1，标点与空白不计。代码默认常规上限 20、焦点上限 200。

焦点指令只影响本次请求，命中多个短语也只提升一次。它是提示词层的长度要求，不把 API 的 `max_tokens` 当作常规控制手段；后者只作为防失控的最终熔断，避免以半句话截断回复。

长度指令必须注入到远程群聊请求临时组装的**系统提醒**中，不修改助理的系统提示词，并放在元数据之前；不能混入用户正文、联系人备注或群聊元数据。推荐顺序为：助理既有系统提示词 → 本次系统提醒中的长度指令 → 远程联系人与群聊元数据 → 本批消息。这样元数据只提供事实，不会稀释或伪装成可覆盖长度规则的内容。

## 回复冷却与能量不足

回复冷却只限制外发频率，不清空待处理消息。巡检周期在冷却期内照常走完；每次发现仍在冷却，就保留消息并开始下一个随机巡检周期。

当能量小于或等于 `0` 时也使用完全相同的等待方式：不把消息丢弃、不额外拉长周期，只等下一个正常的随机巡检周期。能量大于 `0` 的本轮回答可以在外发后把账本扣到负数；从下一轮开始暂停回答，直到自然恢复或正面词变化使能量重新严格大于 `0`。这样，助理不会在刚连续发言后继续抢话，也不会永久沉默。
