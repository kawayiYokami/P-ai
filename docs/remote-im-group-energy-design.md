# 远程群聊能量机制设计

## 目标

让远程群聊中的助理像一个会看群、会控制发言欲望的普通成员：被点名时会尽快看见并理解消息；未被点名时按自己的巡检节奏观察群聊；连续说得多会消耗能量，安静一段时间或收到正面反馈后才更愿意再次参与。

这是当前远程群聊能量机制的说明，实现见 `src-tauri/src/features/remote_im/group_reply_energy.rs`。私聊不经这套能量门控；群聊中**能量仅用于控制非点名巡检是否发起**。点名巡检跳过能量门槛与回复冷却；非点名巡检在秘书评估前需满足 $E > 0$。

## 入场先于巡检

巡检不是收信入口。每条群聊消息先经过 1 秒入站缓冲去重并统一落库；只有消息通过联系人入场模式后，才进入在场观察：

```text
始终入场：通过
点名入场：仅命中点名词时通过
不入场：不通过，只保留消息
```

没有入场，就没有工作台可巡检。联系人曾经在场、曾经回复，或群里正在聊天，都不能绕过这道门槛。

进入在场后，新消息触发看群排期：命中点名走点名加速看群，未命中走常规巡检周期。

## 两类看群路径

### 点名加速：直达主助理，无视能量

@ 助理、点名或唤醒词属于点名加速看群。它们不是传统防抖延后，而是把看群闹钟缩短到极短间隔（通常 1~2 秒）：

```text
本次看群时间 = 当前时间 + 点名加速秒数
```

点名加速留出 1~2 秒仅用于合并对方手快分段补发的内容。到期后：
1. **跳过能量门槛，跳过回复冷却**：即使当前群能量为负数，点名依然必定回复；
2. **不经过秘书判断**：直接由主助理读取旧游标到最新的本次观察区间进行处理；
3. **外发扣能**：主助理外发时按字数扣减能量，扣成负数也照扣，负数绝不阻挡正在进行的回复。

等待期间若群友继续发言，新消息静默入库，不顺延点名闹钟。

### 常规巡检周期（非点名）：由秘书判断，能量受控

常规巡检是联系人维度的周期性看群节奏。

有新消息入库且当前无看群闹钟时，排定一次周期：

```text
本次巡检间隔 = max(1 秒, 常规基础间隔 × (1 + Uniform[-波动阈值, +波动阈值]))
```

例如基础间隔为 60 秒、波动阈值为 0.2 时，每次巡检间隔在 48–72 秒之间。

**等待期间群友继续刷屏**：新消息统统静默入库，**闹钟绝不顺延、绝不重置**。若等待期间突遭点名，闹钟立即升级为点名加速，提前看群。

到期后，由观察员结算群成员正负词与自然回能，推进游标，并由回应判断员裁决：
- 若当前能量 $E \le 0$：**游标不动**，仅重置下一次看群闹钟，等待群友说好话或自然回能，本轮结束；
- 若当前能量 $E > 0$：交给秘书模型评估是否和助理相关、是否是合适的发言时机。

## 一个巡检周期的处理顺序

1. 闹钟到期，观察员读取旧游标到最新消息之间的「本次观察区间」（若原游标目标被压缩删除，则直接重置游标）。
2. 观察员对区间内的群成员发言结算正面词与负面词净值，结合时间计算自然恢复量，推进游标，更新群能量分。
3. 若为点名路径：跳过能量检查与冷却，直接交付主助理。
4. 若为非点名路径：
   - 若当前能量 $E \le 0$ 或处于回复冷却期：不调用秘书，不丢弃消息，游标不动，直接等待下一个看群周期；
   - 若当前能量 $E > 0$：调用秘书模型判断是否需要回复。
5. 若决定回复（点名直达或秘书决定回复）：交付主助理启动独立委托，按字数扣除能量；若秘书决定不回复，本轮自然结束。

因此，非点名能量小于或等于 `0` 时游标不动，助理会在能量自然恢复或被正面词提升到严格大于 `0` 后重新获得机会。点名看群与非点名看群不混用：前者直接直达主助理，后者必须经能量门槛与秘书把关。

## 能量账本

每个群联系人维护独立的运行时能量 `E`；渠道保存参数模板，但一个群里的连续发言不会拖慢同渠道的其他群。

```text
-最大能量 M ≤ E ≤ 最大能量 M；E 允许为负数，但不能低于 `-M`
初始能量 = M
E(t) = clamp(-M, M, E(上次记录) + 每秒回能 R × 经过秒数)
```

非点名回复资格只判断巡检时的 `E > 0`。回复结算可以让 `E` 降到 `0` 以下，但最低只能到 `-M`，不能无限累积负债。负值必须原样保存在账本中并继续按上式恢复，不能在读取或保存时强制改写为 `0`。当恢复或正面词变化使 `E` 再次严格大于 `0` 后，下一轮才恢复非点名回复资格。

能量恢复采用按需计算，不为每个联系人创建后台计时器。每个联系人只持久化 `energy` 与 `energy_updated_at`；在巡检检查回复资格、结算正负词或结算外发回复时，根据当前时间与 `energy_updated_at` 的差值计算恢复量。发生正负词变化或回复扣费时，把结算后的能量和当前时间一起保存。

```text
联系人检查点：energy、energy_updated_at
后台计时器：无
恢复触发：巡检资格检查 / 正负词结算 / 回复结算
状态写回：能量发生实际结算时
```

回能速度是渠道参数 `energyRecoveryPerSecond` 的直接数字，界面文案叫「回复热情 / 每秒回能」，默认每秒回能 `0.6`（`M=100` 时约每分钟 36）。

## 逐轮正文外发与按字数消耗能量

回复不采用“每条固定扣能”，也不采用“生成全部结束后一次性扣能”。

主助理在多轮工具调用循环中，**采用逐轮外发模式：每轮模型产出正文后，先立刻通过平台外发给群成员，并当场按本次正文字数扣减能量，然后再执行当前轮次的工具调用**。

```text
本次消耗 = 基础发言消耗 + 本次有效字数 × 每字消耗
E(外发后) = clamp(-M, M, E(外发前) - 本次消耗)
```

“有效字数”使用实际外发文本去除 Markdown 标记后的非空白字符数；图片、文件和工具调用本身不计字数，图片说明文字照常计算。

扣费规则：
- 扣减不设 `0` 下限，设置 `-M` 下限，允许结果为负数；
- 扣成负数照样完成外发，负数绝不阻挡正在进行的回复与后续轮次；
- 外发结果（无论成功、网络超时或失败）只记日志，调度绝不停摆，继续执行工具或后续轮次；
- 某轮正文为空（仅包含工具调用）时不发也不扣能。

推荐初始参数：

| 参数 | 代码默认值 |
|---|---:|
| 最大能量 | 100 |
| 基础发言消耗 | 14 |
| 每字消耗 | 0.12 |

对应的消耗为：

| 实际字数 | 20 | 40 | 80 | 200 |
|---:|---:|---:|---:|---:|
| 消耗能量 | 16.4 | 18.8 | 23.6 | 38.0 |

配置只需保证最大能量大于 `0`，基础发言消耗与每字消耗非负且有限；不再要求任何预计长度的回复成本小于最大能量，因为回复资格不以“能量足够覆盖本次成本”为条件。

## 正面词与负面词

每个渠道增加两套可编辑短语列表：正面词与负面词。它们只读取其他群成员新发出的文本，不读取助理自己的消息、历史引用或转发内容。

巡检冻结消息范围后，才更新当前群的能量：

```text
E = clamp(-M, M, E + 正面命中奖励 - 负面命中扣除)
```

正负词结算同样不设置 `0` 下限，但设置 `-M` 下限。负面词可以把能量降到负数但不能低于 `-M`；正面词可以从负数开始回升，并在结果严格大于 `0` 时恢复本轮后续的回复资格。

推荐默认幅度：

| 事件 | 默认变化（M=100） |
|---|---:|
| 命中一条正面词 | +6 |
| 命中一条负面词 | -15 |

匹配与防刷规则：

- 按短语匹配。默认正面词是「厉害」「像人」，负面词是「够了」「烦」「串了」；其中「烦」是单字。
- 同一轮巡检范围内，相同正面短语只计一次；正面和负面短语可分别命中后取净值。
- 本轮正、负变化各自最多为 `20% × M`。
- 巡检重排时保留“本轮能量已结算”标记，不重复处理同一冻结范围；应用重启后该轮自然放弃，不补算。

## 焦点指令

每个渠道增加一套可编辑的“焦点指令”短语。它表示群成员正在要求助理用心处理当前问题，例如：

```text
分析 好好想想 深入分析 认真想想 方案设计 评估 推导 复盘
```

命中焦点指令时，本批消息标记为 `focus=true`。它不强制回复、不绕过点名/非点名巡检规则、不绕过回复冷却，也不绕过 `E > 0` 的回复资格检查；本轮外发结算后仍允许能量降为负数。只有助理最终决定回复时，才切换本次注入给 LLM 的长度指令。

渠道配置提供一个“回复字数限制”控件，包含两个独立值：

| 参数 | 建议默认值 | 含义 |
|---|---:|---|
| 常规回复字数 | 20 | 未命中焦点指令时的回复上限。 |
| 焦点回复字数 | 200 | 命中焦点指令时的回复上限。 |

保存时校验 `常规回复字数 ≥ 1`、`焦点回复字数 ≥ 常规回复字数`。两者均由用户单独设置，不写死为 20 或 200。

| 本批状态 | 注入给 LLM 的长度指令 |
|---|---|
| 默认 | `请在 {常规回复上限} 个有效文本单位内进行回应。{计数规则}` |
| 命中焦点指令 | `请认真回答，最多 {焦点回复上限} 个有效文本单位。{计数规则}` |

计数规则：中文 / 日文 / 韩文按可见字形计 1，英语等按 Unicode 单词计 1，数字词和 Emoji 各计 1，标点与空白不计。代码默认常规上限 20、焦点上限 200。

焦点指令只影响本次请求，命中多个短语也只提升一次。它是提示词层的长度要求，不把 API 的 `max_tokens` 当作常规控制手段；后者只作为防失控的最终熔断，避免以半句话截断回复。

长度指令必须注入到远程群聊请求临时组装的**系统提醒**中，不修改助理的系统提示词，并放在元数据之前；不能混入用户正文、联系人备注或群聊元数据。推荐顺序为：助理既有系统提示词 → 本次系统提醒中的长度指令 → 远程联系人与群聊元数据 → 本批消息。这样元数据只提供事实，不会稀释或伪装成可覆盖长度规则的内容。

## 回复冷却与能量不足

回复冷却只限制外发频率，不清空待处理消息。巡检周期在冷却期内照常走完；每次发现仍在冷却，就保留消息并开始下一个随机巡检周期。

当能量小于或等于 `0` 时也使用完全相同的等待方式：不把消息丢弃、不额外拉长周期，只等下一个正常的随机巡检周期。能量大于 `0` 的本轮回答可以在外发后把账本扣到负数；从下一轮开始暂停回答，直到自然恢复或正面词变化使能量重新严格大于 `0`。这样，助理不会在刚连续发言后继续抢话，也不会永久沉默。
