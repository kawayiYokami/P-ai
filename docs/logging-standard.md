# PAI 日志写法标准

本文件规定运行时日志的级别判定、格式、前缀与内容口径。新增或修改日志前先对照本文。

## 一、适用范围

`runtime_log_error` / `runtime_log_warn` / `runtime_log_info` / `runtime_log_debug` 四个函数的调用，以及带 `[TRACE]` 前缀的执行追踪。

不适用于：单元测试输出、构建日志、第三方库日志。

## 二、级别判定

每条日志只问一个问题：**出问题时，我会不会去翻它？**

| 级别 | 判定 | 典型场景 |
|---|---|---|
| **error** | 用户能感知的失败，且需要人介入 | 消息发送失败、数据库写不进去、更新包校验不通过 |
| **warn** | 本该成功但没成，系统降级继续 | 压缩失败退回空摘要、附件外部化失败但消息照常入库、请求重试 |
| **info** | 用户能感知的事件，或关键流程节点 | 收到消息、发出回复、压缩完成、撤回完成、服务启动 |
| **debug** | 开发者排查细节 | 状态快照、变量值、执行到哪一步、缓存命中 |
| **trace** | 逐条执行追踪 | 每条事件解析、每次字段读写 |

### 不算 error / warn 的

以下都是正常分支，用 info 或 debug，不要用 warn / error：

- 联系人未开启收信，跳过处理
- 游标消息已被更早的压缩吃掉，退回触发消息
- 低频群跳过压缩
- 渠道未连接，静默跳过
- 文件不存在、目录不存在

### 不算 info 的

- 每次窗口失焦 / 获得焦点触发的检查 → debug
- 订阅注册、缓存刷新、锁获取 → debug
- 每条入站事件的解析细节 → trace
- 循环体内每条记录的状态 → debug（且只打聚合）

## 三、格式规则

### 硬规则

1. **一条日志一句话**，中文叙述，不用 JSON、不用 `{}`、不用引号包裹字段
2. **字段用 `key=value`**，key 用中文
3. **禁止打印 Rust 类型**：`Some(x)`、`None`、`Ok(...)`、`ThreadId(n)`、`Arc<...>` 等 Debug 输出
4. **禁止打印 JSON 原文**：参数、返回值、配置项一律转成一句话描述
5. **禁止打印内部 ID**：UUID、`agent-1793742686::9947b382`、`remote-im-1773532071655`。写人能认的名字；拿不到名字就不打这个字段，不要退回去打 ID
6. **前缀只保留一层**，取值见第四节
7. **单行不超过 200 字符**。超了说明该拆成一句话描述，不是把 JSON 塞进去

### 对照示例

| 现在 | 应该 |
|---|---|
| `[聊天] 工具循环刷新缓存 conversation_id=9947b382 trusted_input_tokens=Some(331992) context_window_tokens=512000` | `刷新工具循环缓存 会话=9947b382 输入=331992 窗口=512000` |
| `[聊天] 会话写入口, 持有完成, task=append_tool_event_to_assistant_message, conversation_id=9947b382, 线程=tokio-rt-worker:ThreadId(4698), 持有毫秒=51` | `写入工具事件 会话=9947b382 耗时=51ms` |
| `[工具调试] 内置工具执行开始 name=update args={"path":"E:\\github\\...","old_str...` | `开始执行工具 工具=update 目标=ShellDialogsHost.vue` |
| `[运行日志] [录音] 失焦取消检查 {"reason":"cold_start","foregroundActive":false,"recording":false}` | `录音未启动，窗口失焦（冷启动）` |
| `[远程IM][OneBot v11 事件][trace] channel_id=remote-im-1773532071655, message_type=group, user_id=289104862, message_id=1111901072` | `收到群消息 群=fairy的情报室 发送者=红豆泥` |

### 字段命名

日志字段一律用中文名。以下是高频键的固定映射，新增键按同样风格命名（中文、简短、名词）：

| 英文键 | 中文名 |
|---|---|
| `conversation_id` / `session_id` / `session` | `会话` |
| `contact_id` | `联系人` |
| `channel_id` | `渠道` |
| `message_id` | `消息` |
| `delegate_id` | `委托` |
| `agent_id` | `人格` |
| `server_id` | `服务` |
| `block_id` | `块` |
| `record_id` | `记录` |
| `task` / `task_name` | `任务` |
| `duration_ms` / `elapsed_ms` / `cost_ms` | `耗时`（值写 `51ms`） |
| `entry_count` / `count` / `total` | `数量` |
| `status` | `状态` |
| `mode` | `模式` |
| `round` / `round_index` | `轮次` |
| `error` / `err` | `原因` |
| `reason` | `原因` |
| `path` / `file` | `文件`（只写文件名，不写全路径） |
| `tool_name` / `name` | `工具` |
| `model` | `模型` |
| `tokens` / `input_tokens` / `output_tokens` | `输入` / `输出` |
| `error` / `err` | `错误`（与 `reason` 区分：错误是异常，原因是分支理由） |
| `session` | `会话键`（`agent-x::y` 这种复合值用这个，纯 id 用 `会话`） |
| `args` / `arguments` | `参数` |
| `result` | `结果` |
| `action` | `动作` |
| `source` | `来源` |
| `kind` | `类型` |
| `role` | `角色` |
| `query` | `查询` |
| `warning` | `警告` |
| `api_config_id` / `api_id` | `模型配置` |
| `message_count` | `消息数` |
| `entry_count` | `条数` |

同一行里出现语义重复的键时，用限定词区分，不要留英文：`reason`+`error` → `原因`+`错误`，`session`+`conversation_id` → `会话键`+`会话`。

## 四、前缀固定集合

只允许以下 7 个前缀，新增前缀必须在本节登记：

| 前缀 | 覆盖范围 |
|---|---|
| `[聊天]` | 会话、消息、调度、流式、压缩、撤回、分支 |
| `[远程IM]` | 渠道接入、联系人、入站、外发、应答委托 |
| `[工具]` | 工具调用、执行、审查、补丁 |
| `[委托]` | 委托创建、运行、结果回写 |
| `[记忆]` | 记忆写入、检索、回灌 |
| `[系统]` | 窗口、托盘、更新、启动、退出 |
| `[存储]` | 消息存储、SQLite、迁移、备份 |

原来分散的前缀按上表归并。例如 `[聊天流式订阅]`、`[会话写入门]`、`[聊天流诊断]` 统一并入 `[聊天]`。

## 五、一条链路只留关键节点

同一个用户动作拆成多行日志是当前噪音的主要来源。规则：

- **一次工具调用**：只在结束时打一条 info（`执行工具 工具=update 结果=成功 耗时=12ms`）。开始、参数、中间态全部 debug
- **一次模型请求**：只在完成时打一条 info（`模型请求完成 轮次=4 模型=... 输入=331992 耗时=...`）。阶段切换全部 debug
- **一次入站消息**：只在入库完成时打一条 info。事件解析、去重、缓冲全部 trace
- **一次压缩**：开始一条、完成一条。中间的分页读取、瘦身计数全部 debug

## 六、检查清单

新增或修改日志时逐条过：

- [ ] 级别符合第二节的判定问句
- [ ] 没有 JSON、没有 `Some(...)`、没有 `ThreadId(...)`
- [ ] 没有 UUID 或内部复合 ID
- [ ] 前缀在第四节固定集合内
- [ ] 单行 200 字符以内
- [ ] 同一条链路上不会出现第二条第 5 节列出的重复日志
- [ ] 字段名用中文，`key=value` 用空格分隔

## 七、例外

- 崩溃现场、panic 兜底、启动早期日志可以不受格式约束，但级别必须正确
- 迁移与备份类日志保留原样，它们是一次性运维动作，不进日常日志流
